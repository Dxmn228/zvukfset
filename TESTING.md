# Проверка опубликованного сайта

Основной набор проверяет **https://zvukfest.de3.netrun.io** через настоящий
HTTP API и браузеры. Локальный Django-сервер, Docker, PostgreSQL и файл `.env`
для этого не нужны. Запросы идут с вашего компьютера к backend на хостинге.

## Папка запуска и установка

Команды рассчитаны на вашу текущую папку:

```text
C:\Users\Дрыл\Downloads\Telegram Desktop\zvukfest\zvukfest
```

В ней есть папка `zvukfest` с `manage.py` и окружением `.venv313`.
Если терминал открыт рядом с `manage.py`, сначала выполните `cd ..`.
Если рядом с `TESTING.md` — сначала `cd zvukfest`.

Активация в PowerShell:

```powershell
./zvukfest/.venv313/Scripts/Activate.ps1
```

Активация в Git Bash:

```bash
source zvukfest/.venv313/Scripts/activate
```

Зависимости только для удалённых проверок:

```bash
python -m pip install -r ../requirements-hosting.txt
python -m playwright install chromium firefox
```

## Все проверки сайта

```bash
python ../scripts/run_site_tests.py
```

Запускаются проверки HTTP, функций через API и интерфейса в Chromium и Firefox.
Скрипт сам выбирает конфигурацию и абсолютные пути; рабочая папка тестового
процесса всегда корень репозитория. Нагрузочные проверки запускаются отдельно.

Полный запуск создаёт отдельные тестовые аккаунты, обращения и учебные заказы
в базе сайта. Адреса имеют вид `hosting-test-…@example.invalid`. Чужие корзины
и профили не изменяются. Билеты читаются из каталога, цены и наличие не
редактируются. Для сценариев покупки нужен хотя бы один доступный билет.

Тестовые записи остаются в базе: публичного API удаления аккаунтов нет.
Список аккаунтов сохраняется в `artifacts/hosting/accounts.jsonl`, а email
и номер заказа исходного сквозного сценария — в XML. По ним можно удалить
учебные записи через админку. Пароли генерируются и не записываются в файлы.
Не включайте `--showlocals` или трассировки с реальными учётными данными.

## Отдельные наборы

Функции приложения через API сайта:

```bash
python ../scripts/run_site_tests.py --suite api
```

Интерфейс в двух браузерах, включая реальные формы и покупку:

```bash
python ../scripts/run_site_tests.py --suite ui
```

Доступность, HTTPS, ресурсы, API и настройки безопасности без создания аккаунтов:

```bash
python ../scripts/run_site_tests.py --suite checks
```

Все проверки без создания пользователей, обращений и заказов:

```bash
python ../scripts/run_site_tests.py --no-writes
```

Один браузер, видимое окно или фильтр по названию:

```bash
python ../scripts/run_site_tests.py --suite ui --browser chromium --headed
python ../scripts/run_site_tests.py --suite api -k password
python ../scripts/run_site_tests.py --suite ui -k cart
```

Обнаружение тестов без подключения к сайту:

```bash
python ../scripts/run_site_tests.py --collect-only -q
```

Другой опубликованный экземпляр:

```bash
python ../scripts/run_site_tests.py --url https://your-test-site.example.com
```

Адрес также задаётся переменной `HOSTING_BASE_URL`. URL должен использовать
HTTPS и не содержать логин, пароль или путь после домена. Сертификат проверяется.

## Что проверяется

Функциональные тесты вызывают публичные маршруты `/api/…` и проверяют:

- регистрацию, обязательные согласия, email, телефон и подтверждение пароля;
- дубликаты email, повторный вход, смену аккаунта и неверный пароль;
- «Запомнить меня», смену пароля, сохранение текущей и прекращение другой сессии;
- профиль, валидацию, изоляцию пользователей и запрет повышения роли;
- обращения: валидацию, сохранение, историю и закрытость чужих данных;
- поиск, ограничение истории, просмотр карточек и некорректные запросы;
- корзину: сохранение, очистку, количества, изоляцию, скидки и округление;
- заказ: пустую корзину, неверный UUID, устаревшую сумму, повтор без дубликатов,
  очистку корзины и сохранение истории после повторного входа;
- CSRF для форм и защищённых операций.

В браузере проверяются страницы, ресурсы, ошибки JavaScript, mixed content,
каталог, регистрация, вход, профиль, пароль, выход, обращение, отображение
пользовательского текста, описание билета, корзина и учебный заказ.
Дополнительно: слайдер, мобильное меню, клавиатура, подписи полей, ссылки
на документы и ширины 360/768/1440 px. Внешние ресурсы не подменяются локальными.

Проверки публикации включают DNS, TLS и срок сертификата, HTTP → HTTPS,
страницы, минимум 10 внутренних ссылок и якоря, стили админки, health API,
скачивание политики, закрытые маршруты, Secure-cookie, защитные заголовки,
отсутствие DEBUG-страниц и недоступность конфигурационных файлов.
Перед тестами сайт может пробуждаться до 60 секунд: временные ответы
502/503/504 повторяются с паузой 2 секунды. Остальные ошибки не скрываются
повторными попытками. Обычные запросы имеют таймаут 20 секунд.
Загрузка главной страницы после пробуждения сравнивается с 3 секундами.
Кеш браузера при этом пустой; в замер входят картинки, скрипты и внешние
ресурсы, задерживающие событие `load`. Это не только время ответа backend.

Для диагностики скорости отдельно запустите два теста:

```bash
python ../scripts/run_site_tests.py --suite ui --no-writes -k homepage_load_budget --junitxml=artifacts/hosting/performance-results.xml
```

Подробности находятся в `artifacts/hosting/performance/homepage-chromium.json`
и `homepage-firefox.json`: TTFB, готовность DOM, полная загрузка, время и размер
ресурсов, незавершённые запросы. Для внешних ресурсов браузер может не раскрывать
размер без разрешающего заголовка сервера; ноль не обязательно означает кеш.
Падение с `Homepage load took ...` означает превышение порога, а не само по
себе неисправность теста. Порог можно явно изменить через
`--hosting-load-seconds`, но это меняет критерий проверки, а не ускоряет сайт.

Для входа в админку задайте `HOSTING_ADMIN_EMAIL` и `HOSTING_ADMIN_PASSWORD`
в окружении процесса. Без них этот сценарий помечается `SKIPPED`. С ними тест
входит и открывает форму товара, но не сохраняет товар.
`SKIPPED` означает «не выполнено», а не «успешно».
Ошибки Secure-cookie или DEBUG исправляются в настройках публикации; выключение
DEBUG также требует правильной раздачи статики админки.

## Отчёты

Пути отсчитываются от корня репозитория, рядом с `TESTING.md`:

- `artifacts/hosting/all-results.xml` — полный запуск;
- `artifacts/hosting/api-results.xml` — функциональный API;
- `artifacts/hosting/ui-results.xml` — браузеры;
- `artifacts/hosting/checks-results.xml` — публикация и безопасность;
- `artifacts/hosting/layouts/<браузер>/` — адаптивность;
- `artifacts/hosting/accounts.jsonl` — тестовые аккаунты для ручной очистки.

Повторный запуск перезаписывает XML своего набора. Для отдельного отчёта:

```bash
python ../scripts/run_site_tests.py --suite api --junitxml=artifacts/hosting/api-new.xml
```

`pytest.ini` теперь выбирает удалённые тесты, `pytest.ui.ini` — удалённый
интерфейс. `pytest.hosting.ini` используется скриптом для выбора наборов.
Предпочтителен запуск через скрипт: он задаёт папки явно даже при запуске
из вложенного каталога. Chromium проверяет движок Chrome; для установленного
Chrome используйте `--browser chromium --browser-channel chrome`.

## Нагрузка на сайт

По 100 GET-запросов к главной странице с отдельным запросом для пробуждения.
Если первый этап показывает ошибки, не повышайте нагрузку.

```bash
python ../scripts/run_hosting_load.py --url https://zvukfest.de3.netrun.io --concurrency 10 --output ../artifacts/hosting/load-c10.json
python ../scripts/run_hosting_load.py --url https://zvukfest.de3.netrun.io --concurrency 50 --output ../artifacts/hosting/load-c50.json
```

Сохраняются HTTP-статусы, ошибки, RPS, среднее время, p95 и длительность.
Время включает сеть, TLS и HTML, но не подготовку клиентов и не загрузку
изображений/JavaScript. Цель: ноль ошибок и p95 ≤ 500 мс. При превышении
порога отчёт сохраняется, а команда возвращает код 1. Короткие прогоны не
определяют предел пользователей или длительную устойчивость. Для CPU/RAM
используйте мониторинг хостинга.

## Какие проверки нельзя выполнить через URL

Тесты API проверяют поведение функций приложения, но не являются unit-тестами
отдельных Python-функций и не измеряют покрытие серверного кода. Ограничения
таблиц, миграции, искусственный сбой транзакции, перезапуск PostgreSQL и
восстановление резервной копии требуют среды backend и отдельной тестовой базы.
Они не входят в удалённый набор и не считаются пройденными по `/api/health`.
Проверки изменения/удаления товаров и скидок через ORM, намеренного сбоя БД и
параллельного оформления остались в техническом наборе, а не перенесены на
рабочие данные. Удалённые тесты используют существующие билеты.

Сохранены технические наборы для проверки исходного кода в изоляции.
Это не команды проверки опубликованного сайта:

```bash
python -m pip install -r zvukfest/requirements-test.txt
python -m pytest -c ../pytest.local.ini zvukfest/tests zvukfest/zvukfest/tests -p no:cacheprovider -q
python -m pytest -c ../pytest.ui.local.ini zvukfest/tests/ui -v
python ../scripts/run_postgres_tests.py
```

Последняя команда требует Docker и локального `postgres:17`; она использует
отдельный временный PostgreSQL и `pytest.local.ini`. Рабочая база не используется.
Эти наборы можно запускать в CI или в тестовом окружении на сервере.

Для лабораторного отчёта отдельно сохраните WAVE и Chrome DevTools → Lighthouse
(Performance, Accessibility, Best Practices, SEO). Цели: Accessibility ≥ 90,
Performance ≥ 80. Базовые проверки pytest не заменяют эти аудиты. Сохранность
после деплоя, резервные копии, схема БД и логи миграций проверяются отдельно
через панель хостинга и на копии базы.
